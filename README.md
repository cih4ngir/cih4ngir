## `[ SIGNATURE HOLOTAPE ]`

### `HOLOTAPE 01 — SCHEMA CARTOGRAPHER`
*An LLM-powered data extractor & automated data dictionary, built to de-risk an enterprise ERP migration.*

Migrating an ERP means first answering a question nobody can answer: **what is actually in there?** Hundreds of tables, no documentation, live business logic. So I built the thing that answers it.

```
   ┌──────────────────┐    ┌──────────────────┐
   │  LEGACY ERP DB   │    │   D365 F&O API   │     source-agnostic by design
   └────────┬─────────┘    └────────┬─────────┘
            │                       │
            └───────────┬───────────┘
                        ▼
              ╔═══════════════════╗
              ║   ADAPTER LAYER   ║   swap sources mid-migration,
              ╚═════════╤═════════╝   zero rewrites downstream
                        ▼
              ┌───────────────────┐
              │ SQLAlchemy        │   schema reflection ·
              │ metadata engine   │   relationships · profiling
              └─────────┬─────────┘
                        ▼
              ┌───────────────────┐
              │ LangGraph agent   │   stateful graph · tool calls ·
              │ + Qwen3 / Ollama  │   fully local, no data leaves the VPC
              └─────────┬─────────┘
                        ▼
        ┌───────────────┴───────────────┐
        ▼                               ▼
  ┌───────────┐                   ┌───────────┐
  │  FastAPI  │  machine-readable │ Streamlit │  human-readable
  │  service  │  data dictionary  │  console  │  chat over the schema
  └───────────┘                   └───────────┘
```

**Why it matters:** local inference means regulated enterprise data never leaves the network. The adapter pattern means the tool keeps working *during* a gradual migration instead of breaking on day one.
